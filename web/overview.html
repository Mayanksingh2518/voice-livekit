System overview

Care Call Pipeline

How one outbound healthcare call travels from a patient record to a scored trace: who dials, what the agent is allowed to say, where the booking becomes a fact, and how every call ends up auditable in Opik.

The path of one call

Six stages. The interesting part is what moves between them — in particular that the tool record travels separately from the transcript, and outranks it at the end.

What each stage owns

Dispatch
Loads the patient, checks consent and do-not-call, creates a room and dispatches the agent into it. A refused patient is stopped before a worker exists at all. scripts/dispatch_call.py · web/server.py · services/patients.py
Connect
Either create_sip_participant dials the patient's phone, or a browser joins the room. The agent's behaviour is identical either way — only who arrives in the room differs. main.py
Converse
Identity is confirmed before any health data is spoken. Biomarkers are read from the record, never recalled by the model. Requests for medical advice are refused; urgent symptoms escalate. Six tools, each writing to the call record as it runs. agent/patient_agent.py · agent/prompts.py
End
Hangup, the patient leaving, or the duration cap. Every ending — including one nobody answered — produces a result worth logging. main.py · services/call_state.py
Analyse
A structured-output model classifies the call, then reconciliation overwrites anything the system knows for certain and records each correction. No transcript means no LLM call at all. analysis/post_call.py
Observe
Turn traces, a call trace, tool spans, the audio recording and the scores go to Opik. Attaches to the session in one line and never raises into the call. observability/opik_tracer.py

How a call becomes a scored trace

Opik has no "create thread" call — a thread is a set of traces sharing a thread_id. That single fact decides the whole shape.

Decisions worth defending

The observability module

Opik attaches through LiveKit's own session events and a shutdown callback, so the core application changes by exactly one line. The module imports nothing from the app — it takes a session-shaped object and one async callback.

Fail-open: collection runs whether or not Opik is configured. Turning telemetry off changes only where data goes, never whether the post-call analysis runs. A voice agent must not drop a patient because telemetry broke — and OPIK_ENABLED=false proves it.

Manual SDK over the OpenTelemetry integration

Opik ships a LiveKit integration, but it is OTel-based: it auto-captures LLM and TTS spans and then cannot set a thread_id, cannot carry an audio attachment, and has nowhere to put post-call analysis.

So: hand-built tracing in one module. A considered choice, not an unawareness of the integration.
